Welford's recurrence and the sampling mean and variance

First the recurrence formulas for the mean, the sum of squares and the variance, derived step by step. Then m hackers, n systems and a score from 0 to 10: each hacker's sampling mean and variance are computed with those formulas and compared with the true μ and σ².

Exercise 1 · Welford's recurrence formulas

01Starting point: Knuth's recurrence for the mean

Let Mk = (x1 + … + xk)/k be the mean of the first k values. The idea is to write the new mean using the old mean, without keeping the whole sum. Since kMk = (k−1)Mk−1 + xk, adding and subtracting Mk−1 gives:

kMk = kMk−1 + (xk − Mk−1) Mk = Mk−1 + (xk − Mk−1) / k, M1 = x1

The new value only moves the mean by a fraction 1/k of its distance from the old mean. The same relation will be used twice below, written as k(Mk − Mk−1) = xk − Mk−1.

02Derivation for the sum of squares and the variance

The sum of squares is SSk = Σi≤k (xi − Mk)². Expanding the square gives the usual identity SSk = Σi≤k xi² − kMk². As with the mean, I look at what changes when xk arrives. The two sums differ only by xk², so:

SSk − SSk−1 = xk² − kMk² + (k−1)Mk−1²

Replace one factor of the last term using (k−1)Mk−1 = kMk − xk, so that (k−1)Mk−1² = kMkMk−1 − xkMk−1. Then group the terms with xk and those with k:

SSk − SSk−1 = xk² − xkMk−1 − kMk² + kMkMk−1 = xk(xk − Mk−1) − Mk · k(Mk − Mk−1) = xk(xk − Mk−1) − Mk(xk − Mk−1)

The last line used Knuth's relation. Collecting the common factor gives Welford's formula:

SSk = SSk−1 + (xk − Mk−1)(xk − Mk), SS1 = 0

The two factors are the distance of xk from the mean before and after the update. Since xk − Mk = (xk − Mk−1)(k−1)/k, they have the same sign, so SS never decreases, which is what a sum of squares should do. The same fact gives an equivalent form that only uses the old mean: SSk = SSk−1 + (k−1)/k · (xk − Mk−1)².

Variance. The sample variance is sk² = SSk/(k−1) for k ≥ 2. Dividing the last form by k−1, and using SSk−1 = (k−2)sk−1², gives a recurrence directly on the variance:

sk² = (k−2)/(k−1) · sk−1² + (xk − Mk−1)² / k, k ≥ 2

In practice it is simpler to update SS and divide only when the variance is needed, and that is what the code below does.

03Code

The core logic is three lines, with M = 0, SS = 0 and k = 0 at the start:

function push(st, x) {
  const d = x - st.M;      // x_k - M_(k-1)
  st.M += d / ++st.k;      // M_k = M_(k-1) + (x_k - M_(k-1)) / k
  st.SS += d * (x - st.M); // SS_k = SS_(k-1) + (x_k - M_(k-1)) (x_k - M_k)
}

Starting from M = 0 and k = 0 is the same as M1 = x1 and SS1 = 0: the first value gives d = x1, then M = x1, and the second factor is zero. The order of the lines matters, since d must use the old mean and the last line the new one. The memory needed is three numbers, however many values arrive, and every prefix of the data has its mean and variance available at once.

04Why not just use Σx² − (Σx)²/n?

That formula also needs a single pass, and it is correct on paper. On a computer it subtracts two huge, nearly equal numbers, and the rounding errors of both survive the subtraction. Welford's recurrence only works with differences from the running mean, which stay small. To measure this I took 10 000 random integers from 0 to 10, added a large constant (which does not change SS), and compared each method with the exact value, computed in integer arithmetic.

The errors in the table are relative. The one-pass textbook formula is already off by 0.45% with an offset of 106 and by 29% with 107. At 109 the result is meaningless. Welford's error at 109 is still about 10−8. The recurrence is not the most accurate method possible, though: the two-pass formula Σ(x − mean)² has a smaller error at large offsets, but it needs all the data stored and read twice. Welford's advantage is that it gets close to that accuracy while the data streams in. For scores from 0 to 10 with no offset all three are fine, so in Exercise 2 the reason for using it is the running update, not the accuracy.

Exercise 2 · Sampling mean and variance

05The experiment

Each penetration attempt now gets a score from 0 to 10 instead of a 0/1 outcome. Hackers and systems are as in the previous homework: m hackers, each attempting n systems, with all scores independent and identically distributed. I chose a fixed distribution on {0, 1, …, 10} where most attempts score low and a few score high, because a skewed distribution is a harder test than a symmetric one. Two other distributions are available for comparison.

probability of each score

For each hacker j, the n scores go through the recurrence once, which gives:

Mn(j) = sampling mean of hacker j sn²(j) = SSn(j) / (n−1) = sampling variance of hacker j

Then the two averages across the hackers are compared with the theoretical values μ and σ². These come from the exact probabilities, not from the simulation.

What theory predicts. For a sample of size n:

E[Mn] = μ Var(Mn) = σ² / n E[sn²] = σ² Var(sn²) = ( μ4 − σ⁴(n−3)/(n−1) ) / n

Here μ4 = E[(X − μ)⁴]. The results for Mn follow directly from independence. The sampling variance is unbiased because of the identity Σ(xi − Mn)² = Σ(xi − μ)² − n(Mn − μ)². Taking expectations gives E[SSn] = nσ² − n·σ²/n = (n−1)σ², which is why the division is by n−1. I checked E[sn²] and Var(sn²) exactly for the default distribution with n = 3, by enumerating all 11³ possible samples in fractions, and they match.

06Results: averages across the hackers vs. μ and σ²

Each row is a separate experiment with its own random numbers. The z columns give the distance from the theoretical value in standard errors, z = (average − theory) / √(Var/m), using the formulas above. If the averages are only off by chance, z should behave like a standard normal.

Conclusions from the comparison (numbers from the default run, m = 2000):

  • The average of the sampling means matches μ. With n = 100 it is 2.2856 against μ = 2.29. This holds for every n, even n = 2 (2.3022): no large sample is needed, because the sample mean is unbiased at any size.
  • The average of the sampling variances matches σ². With n = 100 it is 6.0093 against σ² = 6.0059. Again this holds at small n (5.8922 at n = 5, 6.2873 at n = 2). The scatter is larger there, but it stays around the true value.
  • The differences are compatible with chance. All the |z| values in the default table are below 2 except one (2.33, for the mean at n = 50). With 20 z values, about one beyond 2 is what one expects, so this is no evidence of bias.
  • Dividing by n instead of n−1 is really biased. The column "SS/n" shows it: at n = 2 its average is 3.14, about half of σ² = 6.01, as predicted by E[SSn/n] = (n−1)σ²/n. The sample mean sits inside the data, so deviations from it are smaller than deviations from μ.
  • Unbiasedness does not carry over to s. The average of sn at n = 5 is 2.22, below σ = 2.45. The square root is concave, so by Jensen's inequality E[s] < σ. An estimator can be unbiased for σ² and not for σ.

why this is useful in inferential statistics

In a real study there is one sample and μ and σ² are unknown: only one hacker's row exists, and the other m−1 are not available. The experiment shows what cannot be seen from one sample: Mn and sn² are random variables with a sampling distribution centred on the true parameters. So a single Mn and sn² are legitimate estimates, with no systematic error in either direction.

The second step is that sn² can stand in for the unknown σ² to measure the precision of Mn: the estimated standard error is sn/√n, and this is what confidence intervals and t tests are built on. The last column of the table tests it directly: for each hacker it computes the 95% interval Mn ± t0.975, n−1 sn/√n, using only that hacker's data, and counts how often it contains the true μ. The share is 0.94 at n = 50 and stays close to 0.95 for larger n. For n = 2 and n = 5 it is only 0.83 and 0.89: the t interval assumes normal data, and this distribution is skewed, so at very small n the nominal level is not reached.

07Effect of n on the variability

  • Both spreads shrink like 1/√n. Multiplying n by 100 divides the standard deviation by 10. In the default run sd(Mn) goes from 0.790 at n = 10 to 0.078 at n = 1000, and sd(sn²) from 3.31 to 0.31. The fitted slopes are −0.503 and −0.508, against the theoretical −1/2. Both estimators are therefore consistent: unbiased, with a variance that goes to zero. More systems per hacker mean each single hacker's estimate gets closer to the truth.
  • The variance is harder to estimate than the mean. In relative terms, sd(Mn) / μ is 0.35 at n = 10, and sd(sn²) / σ² is 0.55. For large n, sd(sn²)/σ² ≈ √((κ − 1)/n), where κ = μ4/σ⁴ is the kurtosis. So it depends on the tails of the distribution, while Var(Mn) only depends on σ². Compare the three distributions: the uniform one has low kurtosis and gives a smaller relative spread than the skewed one.
  • The shape changes too. At n = 5 the sampling variances are strongly right-skewed: a hacker with one lucky 10 gets a large s², and the normal curve does not fit. At n = 1000 both histograms are close to the normal curve, since Mn is an average and sn² is essentially one too.
  • m and n do different jobs. n sets the precision of one hacker's estimates (standard deviation ∝ 1/√n). m does not make any single hacker's estimate better. It only reduces the error of the averages across hackers, by 1/√m. That is why the z columns stay of order 1 for every n.
  • Mn and sn² are not independent here. Cov(Mn, sn²) = μ3/n, which is positive for a right-skewed distribution: hackers with a high average also tend to have a high variance. The simulated value at n = 100 is 0.174 against 0.171 from the formula. For the symmetric uniform distribution μ3 = 0, and the covariance is zero up to noise.
